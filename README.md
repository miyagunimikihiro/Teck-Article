# 技術記事収集アプリケーション(Tech Article Aggregator)

Qiitaの公式API及びZennのRSSフィードから最新記事を自動的に収集し、選択したキーワード(タグ)に基づいてフィルタリングできるwebアプリケーションです。

---

## 使用技術一覧(Tech Stack)

### バックエンド(Backend)
- **言語:** Python 3.11
- **フレームワーク:** FastAPI
- **O/Rマッパー:** SQLAlchemy
- **データベース:** SQLite
- **外部データ連携:** `feedparser` (Zenn RSS解析), `requests` (Qiita API連携)

### フロントエンド(Frontend)
- **フレームワーク:** Flet
- **通信:** `requests` (バックエンドAPIとの同期通信)
  
### 開発環境・インフラ
- **コンテナ化:** Docker/ Docker Compose
- **バージョン管理:** Git / GitHub

 ## こだわった点・工夫した点
 ### 1. アジャイル開発
机上の空論で最初から完璧な詳細設計（データベース構造やAPI仕様）を定義するのではなく、自身の技術的な習熟度や外部APIの不確定要素といった「不確実性」を客観的に考慮し、**アジャイル開発**のプロセスを採用しました。

一気に全てを作り込もうとせず、まずは画面のプロトタイプや最小限の機能（タイトルとURLの保存のみ）を早期に「動く形」にし、その実物をベースに課題や必要な要件（タグ情報の追加やフィルタリングの必要性）を段階的に発見・具体化していくアプローチを徹底しました。

また、機能拡張の単位（スプリント）ごとに専用のフィーチャーブランチ（`feat/...`）を切り、動作検証を完全に終えてから `main` ブランチへマージする運用を徹底することで、手戻りのコストを最小限に抑えつつ、自身の理解度に見合った堅牢なシステムを段階的に構築しました。

### 2. 仕様変更や外部制約に対する柔軟なシステム設計
開発の仮定で直面した外部仕様の制約に対して、以下のバックエンド設計の工夫によってユーザー体験を損なうことなく解決しました。
- **Qiitaの仕様対応:** RSSフィードでは記事固有のタグ情報が取得できなかったため、**Qiita 公式API　v2** を利用するアーキテクチャへと移行し、タグ情報の同期を実現しました。
- **Zennの仕様対応:** ZennのRSSでもタグ情報が取得できない問題が発生したため、記事のタイトルから技術キーワードを自動で判定してタグを擬似生成・保管するロジックをバックエンドに自作しました。

### 3.動的UIと直感的なフィルタリング
フロントエンドにはFlutterベースのFletを採用し、アプリ起動時にバックエンド経由でQiitaのリアルタイム人気タグ一覧を動的取得してドロップダウンを生成する仕組みを構築しました。

## 環境構築・起動方法
本アプリケーションは、Docker及びDOcker Compose環境がインストールされていれば、以下のコマンドだけでバックエンド、フロントエンドの全環境が一度に立ち上がります
### 1. リポジトリのクローンと移動
```bash
git clone https://github.com/miyagunimikihiro/Teck-Article.git
cd Tech-Article
```

### 2. コンテナのビルド及び起動
```bash
docker compose pu --build
```

### 3.　アプリケーションへのアクセス
- **フロントエンド画面(UI):** http://localhost:8502
- **バックエンドAPIドキュメント(SwaggerUI):** http://localhost:8000/docs
